# 늙크크 연구소 — MVP 요구사항

## 현재 화면 범위 (2026-10-16 변경)

사용자 요청에 따라 구글 검색 첫 화면처럼 흰 배경에 이름과 입력창 하나만 둔다. 문장을 입력하고 Enter 또는 화살표 버튼을 누르면 그 아래에 변환 후보 3개를 간결하게 표시한다. 생활형·강도 2·자동 실행을 기본으로 사용하고, 부가 선택지는 노출하지 않는다.

메뉴, 소개 섹션, 판독기, 표현 도감, 스타일·강도 선택, 복사·피드백 UI, 참고 자료·실행 과정 표시는 추후 범위로 미룬다. 관련 백엔드 API와 데이터는 유지한다. 처리 중·오류·샘플·검토 필요 상태는 결과의 의미를 이해하는 데 필요한 최소한의 문구로 표시한다.

아래 내용은 초기 전체 기능 설계이며, 현재 프런트엔드에 노출할 범위는 위 변경 사항을 우선한다.

## 제품 목표

친숙한 생활형 말버릇에서 오는 공감을 문장 변환과 판독으로 경험하게 한다. 첫 화면의 중심은 한 문장을 입력하고 결과를 확인하는 실험실이다. 기본 생성 스타일은 생활형이다.

## 사용자 흐름

1. 말투 실험실에서 생성기 또는 판독기를 선택한다.
2. 직접 문장을 입력하거나 예시 문장을 선택한다.
3. 생성기에서는 스타일과 강도를 고르고 실행한다.
4. 후보·판정과 설명, 참고한 표현을 확인한다.
5. 결과를 복사하거나 공감 여부를 남긴다.
6. 표현 도감에서 200개 후보를 검색하고 스타일별로 살펴본다.

## 기능 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| FR-01 | 한 문장 입력 | 앞뒤 공백 제거 후 2~300자, 공백만 있는 입력 거부, 글자 수 표시 |
| FR-02 | 말투 생성 | 생활형·말장난·추억 채팅 선택, 강도 1~3 선택, 후보 3개와 설명 표시 |
| FR-03 | 말투 판독 | 3종 판정과 근거, AI 사용 시 재미용 점수 표시, 확률·나이로 설명하지 않음 |
| FR-04 | 참고 표현 | 실제 검색된 ID·예문·상황·검토 상태 표시 |
| FR-05 | 품질 검수 | 잘못된 참고 ID·원문에 없는 근거 검사, 수정 1회 제한, 미통과 상태 표시 |
| FR-06 | 표현 도감 | 검색, 스타일 필터, 페이지 이동, 전체/검색 개수 표시 |
| FR-07 | 결과 복사 | 후보 또는 판독 요약을 클립보드로 복사, 실패 시 안내 |
| FR-08 | 결과 피드백 | 공감/아쉬움과 선택적 의견, 중복 클릭 방지, 저장 확인 |
| FR-09 | API 상태 | 서버 연결 상태 및 AI/샘플 모드 구분, 실패를 샘플로 위장하지 않음 |
| FR-10 | 문서 | AI 아키텍처·요구사항·API·로컬 실행법 제공 |

## 화면과 상태

- 화면: 말투 실험실, 표현 도감, 서비스 안내.
- 실험실: 입력 전, 입력 완료, 처리 중, 성공, 검수 미통과, 오류.
- 모드·스타일·강도·입력을 바꾸면 이전 결과를 지워 다른 입력의 결과로 오해하지 않게 한다.
- 중복 실행을 막고, 진행 중 편집은 잠근다. 네트워크 오류에는 재시도 버튼을 제공한다.
- 샘플 모드의 생성 결과는 검색 예문임을 표시한다. 샘플 판독은 판단 보류이며 AI 정확도를 보여주는 것으로 설명하지 않는다.
- 모바일에서는 한 열로 배치하며 키보드 접근, 포커스 표시, 입력 라벨, 상태 알림을 제공한다.

## 비기능 요구사항

- React + TypeScript + Vite, Python 3.12 이상 + FastAPI + LangGraph를 사용한다.
- API 키는 서버 환경변수로만 읽는다. 프론트 번들·로그·응답에 넣지 않는다.
- 입력 및 결과를 DB에 저장하지 않는다. 피드백만 로컬 SQLite에 저장한다.
- OpenAI 요청은 `store=False`로 전송한다. 공급자 차원의 데이터 정책을 앱이 대신 보장하지 않는다.
- 요청 전체 90초 제한, 입력 길이 제한, 로컬 실행용 동시 AI 실행 3건 제한을 둔다.
- 서버는 기본적으로 127.0.0.1에 바인딩한다. 공개 배포 전 인증·비용 제한·보관 정책을 별도로 설계한다.
- 외부 폰트와 이미지가 없어도 화면을 사용할 수 있게 한다.

## 이번 범위 밖

회원가입, 대화 기록, 실제 나이 추정, 자동 웹 수집, 벡터 DB, 자율 멀티 에이전트, 공개 배포, 관리자 라벨링 UI는 후속 범위다. 요구사항은 현재 로컬 개발 MVP를 대상으로 한다.

## 검증 계획

- 데이터 200개와 ID의 일관성, 스타일별 검색 격리, 무관한 검색의 빈 결과 확인.
- 공백·과도한 입력 검증, 오류 응답, 피드백 중복 방지 확인.
- 가짜 제공자로 검수 실패 → 수정 → 재검수 흐름과 재시도 상한 확인.
- 데모 생성·판독, 실 AI 생성·판독의 API 연결 확인. 모델 품질 평가는 별도 과제다.
- 프론트 타입 검사·프로덕션 빌드, 데스크톱·모바일 화면과 주요 조작 확인.
